## Guided workflow: core, circuits, windings and interleaving

Launch `python studio.py`, click **Builder**, and follow:

1. **Core type** — choose 2D/3D, family and part number.
2. **Dimensions** — enter limb/window/yoke dimensions, stack depth, air padding and mesh target.
3. **Material** — select the catalogue, enter linear μr or a 2D reversible B–H curve. **Digitise from graph image…** opens the image digitiser directly. Numeric TXT/CSV import remains available.
4. **Air gaps** — define each limb's gap count and length per gap.
5. **Circuits** — define circuit count, circuit names, winding counts, single/multilayer/interleaved arrangement and radial/axial stacking direction.
6. **Windings** — define each winding's name, total turns, independent current/phase, wound limbs, conductor, packing, material reference, tape and bobbin inputs. Choose 2D full-volume blocks or individual turns.
7. **Interleaving** — generate winding layers, then order them per limb. Layer IDs retain their circuit/winding identity. Odd final layers preserve every turn. P/2–S–P/2 is a packing shortcut.
8. **Nameplate / build** — enter frequency/voltage/current/power ranges per winding, check the model and use it in the workspace. Mesh, solve and save.

A circuit such as **Phase U** contains independent **Primary** and **Secondary** electrical windings. It does not force them to carry the same current or combine their turns. Only physical layers/sections belonging to one electrical winding share a series excitation. This definition is common to 2D and 3D. Sinusoidal snapshot mode optionally evaluates Ipeak × cos(snapshot angle + winding phase); it is still a prescribed magnetostatic point, not an AC or voltage-driven circuit simulation. Phase names do not impose phase angles automatically.

The supplied MATLAB saved state is included as the **Your saved Phase U/V/W** preset: three named circuits, six independent windings, fourteen layers and the decoded interleaving order. Its geometry/material/bundle assumptions and original placeholder nameplate values are flagged for review. All imported field currents start at zero for explicit selection. JSON input is also supplied at `data/user_saved_circuit_workflow.json`. The v0.5 E100 14:16 preset and solved comparison remain available separately.

**2D blocks** distribute each section's ampere-turns over its full rectangle. **Individual turns** generate separate round/litz/foil/rectangular conductor regions, with conforming faceted boundaries for round bundles. Litz strands are homogenized within each bundle. **3D** uses the same hierarchy and packing inputs to position closed ideal-sheet sections; it does not yet solve individual 3D wires or curved toroidal cores. Native section matrices are grouped by electrical winding, and winding-pair results within each named circuit are reported with all other winding currents zero/open.

Standard 3D mesh budget is 44,000 tetrahedra / 10,000 nodes. **Dimensions → Extended 3D budget** explicitly raises it to 120,000 tetrahedra / 24,000 nodes. A preview estimate shows whether the geometry fits the selected budget. The saved fourteen-layer 3D preset needs the extended budget (115,500 tetrahedra at mesh target 4). Its mesh has been generated; a full fourteen-source inductance solve is not claimed. Uncheck **Matrix** beside Solve fields for a field-only solve when appropriate. Pure-Python large 3D solves may be slow.

### Image digitiser

In **Material**, click **Digitise from graph image…**. Load/paste/drop a PNG/JPEG/WebP/BMP screenshot, enter graph limits/scales/units and calibrate three points: A=(Xmin,Ymin), B=(Xmax,Ymin), C=(Xmin,Ymax). Trace one positive monotonic curve. Scroll zooms; Shift/right-drag pans; markers can be dragged, deleted or numerically corrected. Linear and log axes and reversed H/B graph order are supported. Duplicate/non-monotonic/negative/out-of-range points are shown and block application. Explicitly include the (0,0) endpoint when required; this assumption is saved in the source metadata.

Apply the curve directly to a 2D B–H material, export validated SI CSV, or save/reopen an image-bearing session. Images are processed locally in the browser; only numeric curve/source metadata enter the builder recipe. Temperature and frequency are curve labels, not an automatic interpolation or loss model. In 3D, **Store curve · keep linear 3D** retains the data without claiming a nonlinear solve. A perspective photograph must be rectified externally; three-point calibration supports affine rotation/skew, not projective distortion.

`Image_BH_Digitiser.html` is a separate self-contained offline digitiser. It needs neither Python nor the server and exports CSV/JSON for later import. Its example graph is explicitly illustrative, not material data.

Save project JSON and/or the builder recipe. Opening a v0.5 recipe upgrades the hierarchy while preserving its explicit section geometry; regenerating packing switches to the new winding-driven layout. Manual geometry changes after generation are flagged because rebuilding uses the recipe.

### Winding definitions matter

**2D:** Each circuit has signed current I and positive/negative conductor regions. Generated regions carry explicit turn weights: a single-turn side has n=1 and a block has its section turns. Jz=±nI/A in each region. The weights on each polarity separately sum to the series circuit turns. Legacy models without explicit weights distribute total ±NI by aggregate side area. The solver requires both sides. Flux linkage and total energy include the model's out-of-plane stack depth. This planar model omits end effects.

**3D:** A winding window describes the area enclosed by ideal rectangular current loops in x/y, with turns distributed uniformly over its z height. It is not the copper volume. The source potential is `T=(0,0,NI/h)` inside the window; `J=curl(T)` produces closed current sheets on its lateral faces. This release does not model finite wire thickness, copper losses, resistance, skin/proximity effects, or general winding paths.

### Material data

Linear materials use relative permeability `mu_r >= 1`. For 2D nonlinear analysis, add `bh: [[B_T, H_A_per_m], ...]` starting at `[0,0]`. Both columns must increase strictly, with differential permeability at least mu0. The data are piecewise linear in H(B). Above the last point, differential permeability is mu0. Energy is integrated as `integral H dB`; it is not assumed to equal `B*H/2`. The included nonlinear ferrite curve is **illustrative**, not vendor data. No hysteresis or core-loss law is included.

### Boundary, geometry and accuracy limits

- Outer boundary is `Az=0` in 2D, or `n × A=0` in 3D: zero normal magnetic flux. It is not an infinite open boundary. Increase the air-domain dimensions and repeat to quantify truncation effects. Geometry coordinates are absolute and are not rescaled when the domain changes.
- Geometry is limited to 2D rectangles/convex polygons and 3D axis-aligned boxes. Curved 2D turns/toroids are faceted. No STEP/DXF/STL import, curved 3D CAD, Boolean solid kernel or general-purpose CAD mesher is implemented.
- Meshing is global and interface-fitted. Linear 2D supports residual-guided local refinement with an uncalibrated indicator; other modes still use global meshing. A fitted narrow gap can still produce poor element aspect ratios. Mesh diagnostics and an energy trend are not an accuracy certificate.
- P1/lowest-order fields are unsmoothed, piecewise constant per element. Corner peaks can be singular and need not converge pointwise.
- 3D is linear only. Linear 2D AC/eddy currents are now available as documented above. No transient, hysteresis/core-loss, permanent magnet, force/torque, motion, axisymmetric, electrostatic or thermal solver is included.
- Input limits protect this standard-library implementation: 1,200 2D regions / 80 3D core boxes, 16 electrical windings / 32 3D sheet sections, up to 240 total individual 2D turns, 46,000 triangles / standard 44,000 or explicitly selected extended 120,000 tetrahedra, plus node limits. Performance depends on mesh/material contrast and your laptop. This is not a large-model HPC solver.
- Native browser layout and the actual OS file picker have not been tested in this execution environment. A DOM/canvas smoke harness exercised the frontend handlers and actual 2D/3D rendering. Native browser verification remains a release limitation.
- Version 0.1 project JSON used direct current-density regions and has a different schema. Use the current examples/schema; there is no automatic migration of arbitrary old models.
